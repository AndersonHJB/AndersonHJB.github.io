## Question 12

::: tip P376倒数第2行，“尽量平铺直叙处理每种错误”改成“尽量采用扁平化的结构处理每种错误”，是否更好？

- **修改如下：**

    尽量采用扁平化结构来分别处理每一种错误（减少嵌套层级）。

    “扁平化（flattening）”指的是：减少代码的层层嵌套，让逻辑尽可能在同一层级展开，从而提高可读性与可维护性。

    ~~扁平化就是让程序的逻辑路径更直接——少拐弯，少下楼，多走直线。~~

- **看是否需要，我突然想着是否补充一下扁平化**。（个人非常推荐）

    1. **为什么需要扁平化？**

        当代码不断嵌套时，会出现三个典型问题：可读性下降、出错概率上升、修改成本变高。我们来一一说明一下：

        - **可读性下降**：读者需要不断“进入括号”，脑中维护多个条件。

            ```python
            if 是数字:
                if 起始值 < 结束值:
                    if 起始值 >= 0:
                        # 真正的逻辑
            ```

            读到这里，大脑已经开始累了🙂。

        - **出错概率上升**：嵌套越多：漏写 `else`、条件判断错误、缩进问题、忘记 return / break 等情况，都会更容易发生。

        - **修改成本变高**：以后要增加一个条件，你可能要改三层内部代码，这在工程开发中非常致命。

    2. **什么是“扁平化写法”？**

        核心思想只有八个字：**先处理错误，提前结束。**

        也常被称为：

        - Early Return（提前返回）
        - Guard Clause（守卫式判断）

    3. **代码示例**：

        非扁平化（嵌套型）代码示例如下：

        ```python
        if 是数字:
            if start < end:
                print(sum(range(start, end)))
            else:
                print("区间无效")
        else:
            print("请输入数字")
        ```

        逻辑像楼梯——一层一层往下走。

        扁平化写法：

        ```python
        if not 是数字:
            print("请输入数字")
            continue
        
        if start >= end:
            print("区间无效")
            continue
        
        print(sum(range(start, end)))
        ```

        特点非常明显：**每个错误单独处理、没有多余嵌套、主逻辑一眼可见**。——这就是扁平化。

    4. 小结：

        - 版本一：**嵌套结构像走迷宫，而扁平化结构像走直路。** 先把所有“不能通过的路口”挡住，剩下的自然就是正确路径。**优秀程序员不是让代码更聪明，而是让代码更简单。扁平化，本质是在降低理解成本。**
        - 版本二：扁平化就像安检：不符合条件的人直接被拦下，能继续往前走的，一定是合法的。**优秀程序员不是让代码更聪明，而是让代码更简单。扁平化，本质是在降低理解成本。**
        - 版本三：扁平化结构，是指通过提前处理异常或非法情况，减少条件嵌套，让程序的主逻辑保持在更外层，从而提升代码的可读性与稳定性。**优秀程序员不是让代码更聪明，而是让代码更简单。扁平化，本质是在降低理解成本。**
