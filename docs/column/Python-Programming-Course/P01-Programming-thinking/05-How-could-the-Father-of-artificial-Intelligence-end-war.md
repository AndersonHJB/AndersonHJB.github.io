当我们谈起人工智能或编程的历史，几乎绕不开一个名字：**艾伦·图灵**。虽然他没亲手打造出“图灵机”这种理论装置，但他确实设计出了一台改变世界的真正机器——而这台机器的目的，并不是计算数学题、不是游戏、也不是画画，而是……**破解敌人的密码**！

你或许会疑惑：解密码这种事，听上去更像是间谍小说里的桥段，跟编程又有什么关系呢？

别急，我们慢慢说。

## 1. 战争不只是枪炮声

![图灵与同事工作的地方——英国布莱切利庄园，表面上是普通宅邸，实则是情报破译的核心](https://blog.images.bornforthis.cn/docs-images/sha256/db/db6b48b49bb28bcb8c253fe9f688a519667ee0565dbc3984e85e7c19011c48ca.jpg)

时间回到1939年，纳粹德国突然入侵波兰，第二次世界大战正式爆发。世界各国陷入动荡，尤其是英国，时刻担心德国的下一个目标会不会就是自己。全国上下紧张备战，而与此同时，在英国乡下的一座庄园里，一群头脑灵活的数学家，正在执行一项高度机密的任务：**破解德军的通讯密码**。

没错，这是一场无声的战斗，而图灵就是这支“脑力特战队”的核心人物之一。

我们习惯以为战争的胜负要靠枪炮和士兵，但实际上，信息的流通和通讯的安全同样关键。现代战争讲究协同作战，战场信息需要实时传递，这就必须依靠通讯系统。在二战时期，最先进的通讯工具已经不是飞鸽传书或者快马加鞭，而是——**无线电**。

无线电的好处是快，但也有个致命弱点：谁都能“听”到！所以，加密成为了通讯中不可或缺的一环。

## 2. 从恺撒的偏移法说起

你可能会问，这种军事密码和编程思维有什么关系？

其实关系大得很。破解密码，不是靠瞎猜，而是靠**数据分析和模型推演**。图灵的厉害之处就在于，他**把破解密码的问题，变成了可以建模求解的逻辑问题**。

其实，加密这件事古人早就玩过。早在2000多年前，古罗马的恺撒就用一种很简单的办法来保密军令。——恺撒密码

![古罗马恺撒密码的编码方法示意图，例如：A → D, B → E](https://blog.images.bornforthis.cn/docs-images/sha256/98/9845c5ca4638999c8885da81808f017f99a2ba33bf381d30c1bb3896a38eedc6.png)

不过恺撒的做法很简单，他把单词里头的每个字母，都改写成在它后边第三位的字母。比如：把 A 写成 D，把 B 写成 E。到了 X 呢，就**顺延**下去写成 A，Y 和 Z 就写成 B 和 C。这样，每个字母都被新的密码字母替代了。

举个例子：书的英文是 B-O-O-K，book，这个词用恺撒密码来写，就是 ERRN。光看到这三个字母，谁都不会把它跟 book 联系在一起。

当然了，你也可以不顺延三位，而是顺延1位、2位，或者10位、20位，都行。

在古代，本来认识字的人就不多，看到恺撒的密码，那更觉得是天书了，所以，在当时，这样的密码是非常安全的。但随着识字的人变多、破解方法越来越强，这种简单加密很快就不够用了。

恺撒加密被人们发现，使用**频率统计法**就能轻松破解：你在写英文单词的时候，肯定已经发现了，有的字母很常用，有的字母却不常用。比如我现在正在给你写这本书的计算机键盘吧，上面 e、a、d、t 这几个键都磨花了，而附近的 z 和 q 却还很新。很明显，前面那几个字母我经常会敲到，而 z 和 q 却很少用。下图是用典型的英语书写的文字样本中各字母出现频率：

![英文中字母使用频率统计。字母 E、A、T 出现频率最高，破解密码常用到这类统计方法](https://blog.images.bornforthis.cn/docs-images/sha256/1c/1c77eb1ea11abc4ca593dd2329413310c687e111a87d5ed79dee2e71c0dbfb98.png)

如果咱们截获了很多敌人加密的军令，就可以看看哪些字母出现得最**频繁**。比如说在一段密码里，T 和 Q 出现得最频繁，那它们俩很可能实际上就是 E 和 A 了。把这两个字母带进去，就可以一步步尝试得到答案了！

于是，只要统计敌军密码中各字母出现的频率，再反推这些字母在原文中可能代表的含义，**复杂的加密问题就被简化成了一个统计排序问题**——这正是“问题转化”的典型思维。

~~可惜，再高级的加密也逃不过人类聪明的脑袋。因为英文中有些字母用得多，比如E、T、A；而有些字母用得少，比如Q、Z。如果你能截获大量加密信息，就可以通过统计字母频率来“猜”原文，这就是**频率分析法**。~~

再次强调**问题转化**的思路：~~原本是“看不懂的密文”，转化成了“统计哪些字母出现得多”。这个思维方式，其实就是编程中常见的一种思维模式。~~ 这个地方就体现了两个非常重要的编程思维原则，就是“**抽象**”和“**问题转化**”。虽然直接搞懂每个单词的意思很难，但是，我们可以把问题转化成“每个字母出现的频率”。这就把破解密码变成了一个数学问题，咱们只要让机器数一数，每个字母出现了几次，然后根据每个字母出现的频繁程度试几次，问题就能轻松解决了。（“看不懂的密文” ——> “统计哪些字母出现得多”，数一数可是机器会的事情呢。）

## 3. 恩尼格码：密码界的“终极大 Boss”

![德国恩尼格码加密机外观。它的加密方式变化多端，复杂程度惊人](https://blog.images.bornforthis.cn/docs-images/sha256/98/98a05f9d0fe7e6270705de1e584902a7da1cc6241adf1856af650d486c108f47.jpg)

那时候虽然还没有电脑，但人们已经会**编程**了呀，只要制造一台机器，然后告诉机器，每加密完一个字母，就换一套密码表，再加密下一个字母。这样一来，机器就能完成这件复杂的事情。而破译密码的时候呢，只要把这个过程倒过来就行了。

德国人就真发明了一种更复杂的加密方法——每输入一个字母，加密规则就变一次。也就是说，一封电报里，前后两个字母即使一样，加密出来的结果也可能完全不同。

这种加密方式让**统计字母频率**的方法彻底失效。而让它实现的工具，正是当时被德国人视为“国之利器”的机器——**恩尼格码机（Enigma）**。它的机制极其复杂，每加密一个字母，内部就旋转改变一次设置。这意味着相同的字母在密文中会被翻译成完全不同的样子。

**Ps**：“恩尼格码”是德语，翻译过来就叫作“**谜**”，谜语的谜，所以，也有人把它翻译成谜机的。

用今天的话来说就是：如果你想把所有可能的加密方式都列出来，写成一本书，那本书的页数将远远超过整个银河的星星数量，还多出一亿倍！

靠人力试对组合几乎不可能，更别说德国每天都更换密钥，一旦破解速度慢于换密速度，等你破解出来，战役都结束了。

这简直就是密码世界的“终极 BOSS”。



## 4. 图灵的“逻辑打击”：不是靠人解密，用机器来破解机器！

面对这台“谜之机器”，图灵并没有退缩。他意识到，这样的任务不能靠人力解——**就用机器来和机器对抗**。

而**人性，是最大的漏洞！**

他没有试图一页页去翻那本“宇宙级”的密码书，而是敏锐地察觉到一个细节——德军在每天固定时间会发送一条天气预报，而这条电报中总会出现德语的“天气”一词：wetter。（习惯有时也是致命的）

图灵就从这个词入手，先“假设”某段密文中包含 wetter，再尝试反推出密码结构。这个小小的突破，把密码的可能性从亿亿亿下调到了百万种可能。

但就算100万种，用人力也是破译不了的。因为德国一天就会换一套新的密码，如果花了一天以上的工夫才破译出来，那也是白搭——因为要改用新密码了嘛。

图灵设计了一种“密码分析装置”，人称 **“炸弹机（Bombe）”** 。这台机器不是用来打爆什么，而是快速试验成千上万组可能的密钥组合，一旦碰到符合“已知线索”的组合，就能反推出整段电文。这台机器能在一个小时内完成所有尝试，远远快过人类分析。



## 5. 编程思维，在战场上救了无数人

![电影《模仿游戏》剧照](https://blog.images.bornforthis.cn/docs-images/sha256/f3/f363521a116dc59e01f21ba87f417a91d5b7643c1d987989c1f266960376877b.png)

图灵和他团队的努力，为同盟国提前知晓了无数军事情报——敌军部队移动、潜艇攻击时间、空袭计划等等。有人统计，正是因为他们的工作，**第二次世界大战至少提前两年结束，数百万生命被挽救**。

他们的贡献在当时是绝密的，战后图灵并未因此获奖章或荣耀。直到二十年后，相关档案解密，世人才知道他拯救了一个时代。

这背后用到的，其实就是**程序化思维**。

图灵设计机器，不是靠蛮力，而是靠抽象和转化。他把“破解密码”这种看起来玄乎的事，转成了“尝试所有可能”、“筛选固定模式”、“自动执行流程”——这些，正是今天计算机所擅长的。

很多人提起图灵，只记得“图灵测试”或“人工智能的奠基人”。但他最令人敬佩的地方在于：他用**抽象建模**、**逻辑推理**、**自动化工具**，解决了一个看似无解的战争难题。

这正是最核心的编程思维：**把一个现实问题抽象成模型，用系统性方法寻找答案，并让机器执行过程**。

我们再次见证了“建模”和“问题转化”的强大威力。

那么，如果我们想让计算机看懂我们生活中的“图像”或“语言”，是不是也要用类似的方式，把现实转成机器能理解的数据？下一篇，我们一起探究。



## 7. 兴趣选读

### 7.1 🛠 德军的解密流程：其实是“还原”原始设定

恩尼格码的“加密”和“解密”其实用的是**同一台机器**，也就是说——只要你用**完全一样的设置**去输入密文，机器就会自动还原出原文。

这个过程就像：

1. 你用一把奇怪的锁（加密设定）把一个盒子锁上了；

2. 只要另一个人有**完全相同的钥匙**（解密设定），就能打开这个盒子。

### 7.2 🔧 每天的设定是关键！

德军每天早上都会通过纸质的“密码本”来统一加密规则，包括：

1. **转子顺序（Rotor Order）**：选择用哪几个转子；
2. **转子初始位置（Rotor Positions）**：每个转子从哪个字母起始；
3. **插线板连接方式（Plugboard Settings）**：哪些字母互换；
4. **每日密钥（Daily Key）**：规定今天的标准设定。

然后，每台恩尼格码都按照这本密码本上的设置来调整机器。

### 7.3 📝 举个具体流程例子

假设一位德国军官要发送一封电报，步骤是这样的：

1. 他查阅密码本，设置好恩尼格码机器（设定 A）。
2. 他再“随机”选一个会话密钥，比如 `XYZ`，然后把 `XYZ` 用设定 A 加密后写在电报最前面。
3. 之后，他会把机器设置成 `XYZ`，用它来加密正文内容。

接收方就按以下步骤来解密：

1. 查阅当天的密码本，也设置成设定 A；
2. 解密电报最前面的“会话密钥”；
3. 用解出的 `XYZ` 重设机器；
4. 继续解密正文内容。

这样，通信双方虽然每天用的是不同的会话密钥，但只要他们起点一致、机器一致，整个过程就非常稳。

### 7.4 🤔 那德军犯了什么错误？

前面正文已经讲过了，不过这里我还是专门分享一下。

你可能已经猜到了：德国军方虽然密码机制设计得很强，但他们太过**依赖每天“统一的设定”**，并且有不少粗心习惯，比如：

1. 操作员懒得更换“会话密钥”；

2. 有些单位每天用一样的开头语；

3. 密码本不够频繁更换；

4. 密钥本被俘虏或泄漏；

5. 电报开头喜欢写“天气报告”；

6. 常常以“希特勒万岁”结尾；

7. 有些士兵每次用同样的几组字母作为初始设置（比如女朋友名字的缩写）。

这些操作，等于是自己偷偷把钥匙放在门口，被图灵他们盯住后，就成了破绽。

### 7.5 图灵的技巧

恩尼格码每天都会更换设定，意味着每天都有数百万种可能的组合。如果一个个试，那根本来不及。但图灵想到了一种方法：与其一个个尝试，不如“排除不可能”。

他设计了数学模型来**自动排除错误设定**，只留下少量“可能对的组合”。这就好像从一大堆锁里，先剔除明显不对的，把范围缩小。

以及，破解成功后，盟军**并没有立即去阻止每一次攻击**，否则德国人会意识到密码被破了。相反，他们只在关键时刻使用这项情报，比如：

1. 让某些舰船“恰好”绕过潜艇伏击；

2. 偶尔“故意失败”来混淆视听。

这一系列策略被称为“**超密行动（Ultra）**”，帮助盟军赢得了许多战役。



### 7.6 🧠 总结一下

1. 德军自己能解密，是因为**加密和解密用的是同一套机器 + 同样的设定**。

2. 解密靠的是“事先知道正确设置”而不是分析密文。

3. 图灵他们正是通过抓住德军的“操作套路”，逆向推理出设定，从而破解密码。

4. 图灵他们破解恩尼格码，靠的不是蛮力，而是**逻辑推理 + 数学模型 + 机械自动化 + 人类习惯漏洞**，最终战胜了人类历史上最复杂的密码系统之一。
