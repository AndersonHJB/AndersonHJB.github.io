## 1. 基于对象的编程？

![](https://blog.images.bornforthis.cn/docs-images/sha256/54/54b984fc9b1aa4e664523c02896ff6e6c9b0b3195f3ff7da717d2b891615915e.png)

想象一下，你是一个班主任老师，新学期刚开始，学校让你做点小统计：全班的平均身高是多少？你于是让大家报一下身高，快速一算，搞定。

不久之后，学校又让你查一下平均考试成绩。你又得一个个去问同学，数学多少分、语文多少分……虽然这次的数据量大一些，但也很快就算完了。

又过了几天，学校需要统计每个同学的平均体重，你只好再统计所有人的体重信息，算出一个平均体重。

虽然每一次的计算都不复杂，你开始觉得，这活儿是不是太重复了？每统计一次，就要搜集一次数据。这件事太麻烦了，有没有别的办法能够解决这个问题呢？

这时，如果你有点“程序员思维”，可能会灵光一现：“我干嘛不直接给每位同学建个个人档案呢？”

无论身高也好，成绩也好，这些信息都是和学生有关的。我们可以在电脑里给每一位学生**建立一个档案**，把他们的身高、体重、年龄、各科的考试成绩、甚至是家庭住址和家长联系方式全都输进去。

![](https://blog.images.bornforthis.cn/docs-images/sha256/4f/4fce7f9cf62024e1f3b7fbd9016f0290263262aa992c8e46d03689f27a32cee8.png)

这样一来，想查啥信息，直接翻档案就行，不用一遍遍地收集。比如查数学成绩，只需要看每个人档案里的“数学”字段就行了。是不是很省事？具体在计算机里面操作则是：在需要查看的时候，只需要在计算机输入指令，比如：

1. **第一步**：启动 Excel 搜索框，使用快捷键：`Ctrl + F`；
2. **第二步**：接着在搜索框内输入：小明数学 或 小红身高，就能看到对应的信息了。

如果要统计平均身高呢？也可以用一个指令调取全班同学的身高数据。（这里不是教学 Excel 操作，是要你学会思维）

当然，刚开始录入资料可能有点费劲。而且你是不是还有这种感觉：调取档案数据听起来挺方便的，但是在建立档案的时候，输入各种各样的信息也要花很长时间，算下来好像并没有节省时间唉？

但一旦档案建好了，后面的工作就轻松多了。不仅可以快速算平均数，还能看到个别同学的学习变化。（省字版：单独针对某一位同学的档案进行分析）

例如：

1. 小刚数学成绩连续下滑，是不是遇到啥困难了？应该问问小刚需不需要帮助。
2. 小红语文成绩总是很高，是不是这方面有天赋？
3. 小明的英语成绩很好但语文成绩一直很差，那说明他可能**偏科**了。

你有没有发现：你作为班主任最开始采用的办法，是关注每个学生的身体还有学习成绩数据，这些都是临时的不够全面且准确。可随着考试的增加，数据信息越来越多，想搞清楚每一位同学的学习情况就越来越困难。

但如果把班上的每一位同学，看成一个个**对象**。和一个对象有关的身高、体重、成绩数据，都可以看成是对他的描述，通通可以塞进这个对象的档案里，这样就把杂乱的信息给归到了一起。

虽然建立档案前后，要处理的信息数量没变，但因为看问题的角度不同，作为班主任就能更好地关注每一位同学的成长了。

这种看待问题的方式，就和基于对象的编程思路特别一致。

所以，上面这种“为每位同学建一个完整档案”的做法，其实和程序员的一种经典思维很像——**面向对象编程**。

和前面说的蚁群算法、蒙特卡洛算法不同，**基于对象的编程并不是指某种具体的算法**。它的核心就是**按照我们更习惯的角度，去整合数据或者是编写程序**。

这种思想对软件工程师来说特别重要。

## 2. 什么是“面向对象”？其实你早就用过了！

面向对象的本质，就是把一个个事物当作“对象”来看，每个对象都有自己的特征和行为。比如说“学生”这个对象，有“身高”“成绩”等特征，有“考试”“请假”等行为。

其实，我觉得我在本书后续讲 Python 面向对象编程部分会比这里清楚。期待你学完编程思维部分后，到后面再深入探寻**面向对象编程**。

这种思路不仅适用于老师统计数据，对程序员来说，也是一种处理复杂问题的超级利器。

比如，现代汽车里有个“车载计算机”，它需要管理非常多的信息：**发动机温度**、**轮胎气压**、**油箱油量**等等……不同的信息交织在一起，如果全塞在一起处理，那程序就乱套了。

除了记录，计算机还要对不同的情况机型处理，例如：

1. 轮胎漏气了，计算机要让汽车赶紧减速；
2. 如果油量太低，要赶紧提醒驾驶员去加油；

这些参数和代码要是一股脑塞进计算机里就太混乱了。怎么办呢？这时候，**基于对象的编程**就派上用场了。

工程师们最关注的不是这一堆堆数据，而是汽车的各个部件能顺利运行。

![](https://blog.images.bornforthis.cn/docs-images/sha256/f1/f1b068c6de971909a852ac40be8e0ff1b8b7b2352af787c90d1d2149971000d8.png)

所以他们来说，**把发动机、车轮等等部件看成一个个对象**更合适。每个对象拥有自己的一份“档案”，接着就可以像建立学生档案一样，把和发动机、车轮有关的信息都打包好，塞进对应的档案里。

在编写代码的时候，也会专门针对发动机、车轮这些部件编写，比如命令发动机温度过高了就加紧散热。

那你肯定会问了：如果有些问题牵扯到好几个对象怎么办？比如轮胎漏气了要减速，这不就牵扯到轮胎和发动机两个对象了么？不用担心，工程师们会通过一种叫做“**函数**”的东西把各个对象关联起来。比如：轮胎气压太低时，通过函数触发“发动机减速”。

## 3. 用对象思维的三大好处

### 3.1  查错容易

话不多说，先上省字版：**定位问题的时候特别方便。**

比如发动机系统出了故障，你不需要从所有的信息里面去找问题，只需要检查发动机这个对象（发动机的部件档案）里的参数就可以了。如果发动机对象里所有的参数都没有问题，那问题就可能出在和发动机有关的“函数”上。



### 3.2 搬家方便

省字版：**各种各样的数据信息进行打包封装之后，迁移起来特别方便。**

假如你又制造了一款新车，虽然车轮、发动机参数上可能有差别，但大部分信息还是差不多的，这时候，工程师们只需要将之前打包好的对象信息搬到新系统上，做一点小修改就可以了。

其实和学生转班的例子同理：假如有同学去了新的班级，老师也只需要把这个学生的信息档案转到其他班上即可，操作起来方便还不容易出错。只需要修改部分信息即可，例如：班级、学号等。

### 3.3 分工合作更轻松

省字版：**把汽车拆分成更小的单元，可以提升工程师们的效率。**

工程师团队里的大部分人不需要掌握汽车的全部知识，例如：

1. 空调专家专门负责空调这个对象（“空调”档案）；
2. 发动机专家也专门负责发动机程序（“发动机”档案）；
3. 这样一来，几个单元可以由不同的团队设计，最后再统一进行整合，一个复杂系统就诞生了，这种模式和**模块化编程**有点像。

既然有这么多好处，大部分工程师在开发大型软件的时候都会用这种编程方法。



## 4. 用对象思维做饭，也挺香！

![西红柿炒鸡蛋](https://blog.images.bornforthis.cn/docs-images/sha256/13/131f355ee34ade6a8a9b0a2aa7e4a468aac3ae135ddec752e558dac327e67deb.png)

 这种编程思想对生活也特别有用，不信你试试做西红柿炒鸡蛋。

在之前的文字中，我教你用**并行算法**的思维做了**炒鸡蛋**。如果你真的做了这道菜，可能会出现各种各样的问题。

如果你是“步骤式”选手，可能会记一大串流程：打蛋、切西红柿、倒油、炒蛋、再炒西红柿……一不小心顺序搞错，可能油热了鸡蛋没打好，或者蛋炒完发现番茄还在案板上等着你。

但如果你用基于对象的编程思维来看待这事，就不容易出错了。

![](https://blog.images.bornforthis.cn/docs-images/sha256/3b/3b7bcb2064beebca4d7025489d97acb38119a38898cdd10994cf54b0b5e3b4a7.png)

你想，不管炒鸡蛋一共有几步，你需要操作的对象只有3个：**鸡蛋、西红柿、还有调料**。

1. 对于鸡蛋这个对象，要进行的操作就是打碎搅匀；
2. 对西红柿这个对象，进行“切块”处理；
3. 对于调料这个对象，做“准备”工作。

这些步骤是**完全独立的**，可以单独处理好。

处理好之后，这三个对象可以通过“**炒**”这个函数，连接到一起。完成这一步，西红柿炒鸡蛋就完成了。——一道美味就搞定了！是不是比记步骤更方便呢？



## 5. 程序员的脑袋，不只用来写程序

面向对象的编程思想，其实是一种**整理混乱信息、清晰地分工协作、提升效率**的思维方式。它不只是软件工程师的专属工具，也可以帮我们更好地理解生活、解决问题。

所以，下次当你要处理一堆复杂信息时，试着问问自己：“**我能不能把它们整理成几个对象？**”

说不定，你也能像工程师一样，把混乱变成有序，化繁为简！
