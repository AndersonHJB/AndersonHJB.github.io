你现在不要新建 `ja4-crawler-limit`，直接把现有唯一的 `anti-crawler` 从 **IP 计数覆盖成 JA4 计数**。

按照你现在的实际配置：

```text
规则名：anti-crawler
范围：全站所有文件/目录
排除：/assets 和 /assets/*
窗口：60 秒
限制：30 次
当前 Key：IP
超限：deny
```

直接执行下面这一整套。

```bash
# 1. 先确认当前规则
vercel firewall rules list --expand

# 2. 把现有 anti-crawler 从 IP 覆盖为 JA4
vercel firewall rules edit "anti-crawler" \
  --condition '{"type":"path","op":"eq","value":"/assets","neg":true}' \
  --condition '{"type":"path","op":"pre","value":"/assets/","neg":true}' \
  --action rate_limit \
  --rate-limit-window 60 \
  --rate-limit-requests 30 \
  --rate-limit-keys ja4 \
  --rate-limit-algo fixed_window \
  --rate-limit-action deny \
  --yes

# 3. 查看待发布修改
vercel firewall diff

# 4. 发布到生产
vercel firewall publish --yes

# 5. 最终确认
vercel firewall rules list --expand
```

最终你应该看到类似：

```text
anti-crawler [Enabled]

Conditions:
  path does not equal /assets
  path does not start with /assets/

Action: Rate Limit (30/60s)
Rate Limit: 30 req / 60s (fixed_window)
Keys: ja4
If exceeded: deny
```

也就是说现在会从：

```text
同一个 IP
30 次 / 60 秒
```

变成：

```text
同一个 JA4 TLS 指纹
30 次 / 60 秒
```

`/assets` 仍然完全不进入这条规则：

```text
/assets
/assets/app.js
/assets/style.css
/assets/images/xxx.webp
```

而下面这些仍然全部限制：

```text
/
 /blog/*
 /column/*
 /1v1/*
 /api/*
 /robots.txt
 /sitemap.xml
 /favicon.ico
 其它所有路径
```

### 如果想恢复成原来的 IP

直接再覆盖回来即可：

```bash
vercel firewall rules edit "anti-crawler" \
  --condition '{"type":"path","op":"eq","value":"/assets","neg":true}' \
  --condition '{"type":"path","op":"pre","value":"/assets/","neg":true}' \
  --action rate_limit \
  --rate-limit-window 60 \
  --rate-limit-requests 30 \
  --rate-limit-keys ip \
  --rate-limit-algo fixed_window \
  --rate-limit-action deny \
  --yes

vercel firewall diff
vercel firewall publish --yes
vercel firewall rules list --expand
```

关键点就是：**不要 `add` 第二条 Rate Limit，直接 `edit anti-crawler`，只把 `--rate-limit-keys ip` 改成 `--rate-limit-keys ja4`。**这样不会碰你的 Attack Mode、Bot Protection、AI Bots，也不会增加第二条 Rate Limit。
